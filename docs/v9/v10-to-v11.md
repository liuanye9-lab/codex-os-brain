# Upgrading from V10 to V11

V11 is a subtraction release. Nothing in the reliability core changed shape, so an existing V10
install keeps working after the upgrade — but three command groups and one storage layer are gone
for good.

## What was removed

| Removed | Replacement |
|---|---|
| `brain memory *` | Host-native recall (Codex Memories). The harness no longer stores long-term memory. |
| `brain cognition *` | Nothing. The Cognitive Asset Protocol lab was withdrawn, not relocated. |
| `brain embeddings *` | Nothing. The harness never called embeddings on a hook hot path anyway. |
| `brain harness cycle\|candidates` | Nothing. It only drove the memory harness. |
| MCP tools `brain_memory_recall`, `brain_get_cognitive_*`, `brain_read_cognitive_projection`, `brain_get_embedding_*` | Removed from the tool list. |
| Hook registrations for `SessionEnd`, `UserPromptSubmit`, `PostToolUse`, `PermissionRequest`, `SubagentStart`, `SubagentStop`, `PreCompact`, `PostCompact` | Not replaced. See below. |

`--enable-memory` and `--enable-cognitive-assets` now fail with a usage error instead of silently
doing nothing, so a stale script cannot appear to succeed.

## Why the hook surface shrank from 12 to 3

Every remaining hook maps to exactly one failure mode it can actually prevent:

| Hook | Failure mode | Blocking |
|---|---|---|
| `SessionStart` | lost contract context after a new or resumed session | no, fail open |
| `PreToolUse` | action outside the signed task boundary | yes, fail closed |
| `Stop` | completion claimed without passing acceptance | yes, fail closed |

The other eight were observation-only, or duplicated `PreToolUse`. They cost a process spawn per
event and produced no decision.

## Upgrade procedure

```bash
brain hooks disable --project "$PWD" --confirm --json   # restores your pre-install hooks.json
git pull                                                 # or reinstall the package
npm install
brain hooks enable --project "$PWD" --confirm --json
brain doctor --project "$PWD" --json
```

Treat the install as complete only when `doctor` reports `ok=true` together with
`eventsComplete=true`, `fingerprintMatch=true`, `packageVersionMatch=true`,
`runtimeDigestMatch=true`, `runtimeHealthy=true`, `runtimeStorageWritable=true`, and
`evidence-signing-loop=passed`.

The installer rewrites only its own hook groups. If you added your own entries for the eight
now-unregistered events, they are yours: `enable` will not touch them and `disable` will not remove
them.

## Your existing data

Task contracts, events, evidence and the failure circuit live in the control store and are
unaffected — the V9 runtime contract is unchanged, which is why the package is still named
`codex-brain-v9`.

The memory database is a different story. V11 contains no code that reads
`<state>/memory/memory.sqlite3`, its backups, or its encrypted `.cbmem` archives. The upgrade does
not delete them; it simply stops using them. If you kept anything of value there, export it with a
V10 checkout **before** upgrading:

```bash
git checkout v0.16.0
brain memory query --query "" --limit 100 --json > memory-export.json
```

Nothing in V11 will read that file back. Move anything worth keeping into your host's own memory or
into project documentation.
